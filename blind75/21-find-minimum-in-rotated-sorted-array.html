Find Minimum in Rotated Sorted Array

leetcode.com/problems/find-minimum-in-rotated-sorted-array · Blind 75 · FAANG favourite

Problem Statement

Suppose an array of length n sorted in ascending order is rotated between 1 and n times. Given the rotated array nums, find the minimum element. You must write an algorithm that runs in O(log n) time.
Example 1
Input: nums = [3,4,5,1,2]
Output: 1
Rotated array. Minimum is 1.
Example 2
Input: nums = [4,5,6,7,0,1,2]
Output: 0
Original [0,1,2,4,5,6,7] rotated 4 times.
Example 3
Input: nums = [11,13,15,17]
Output: 11
No rotation; minimum is the first element.

Constraints

  • n in [1, 5000]
  • All values unique
  • -5000 ≤ nums[i] ≤ 5000

Approaches Comparison

Approach Time Space Notes
Linear Scan O(n) O(1) Too slow; misses the log n requirement.
Binary Search O(log n) O(1) The minimum is at the inflection point. Optimal.

Approach 1 — Linear Scan O(n)

TimeO(n)

Approach 2 — Binary Search Optimal

TimeO(log n)
SpaceO(1)

The minimum is at the rotation point. Compare nums[mid] with nums[right]: if nums[mid] > nums[right], the minimum is in the right half; otherwise it's in the left half (including mid). 

def findMin(nums):
    left, right = 0, len(nums) - 1
    while left < right:
        mid = (left + right) // 2
        if nums[mid] > nums[right]:
            left = mid + 1
        else:
            right = mid
    return nums[left]

}

Compare Mid with Right, Not Left

Comparing with right (not left) avoids ambiguity when the array isn't rotated. If nums[mid] > nums[right], the right portion has been rotated and the minimum is to the right of mid.

Interview Playbook

  1. Why right, not left? If nums[left] < nums[mid], left might still be the minimum (no rotation). Comparing with right cleanly determines which half is sorted.
  2. Duplicates variant: LeetCode #154 adds duplicates, requiring right-- when nums[mid]==nums[right].
