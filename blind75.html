Longest Consecutive Sequence

leetcode.com/problems/longest-consecutive-sequence  ·  Blind 75 · FAANG favourite

Problem Statement

Given an unsorted array of integers nums, return the length of the longest consecutive elements sequence.

You must write an algorithm that runs in O(n) time.

Example 1
Input: nums = [100, 4, 200, 1, 3, 2]
Output: 4
The longest consecutive sequence is [1, 2, 3, 4]. Length = 4.
Example 2
Input: nums = [0, 3, 7, 2, 5, 8, 4, 6, 0, 1]
Output: 9
Sequence: [0,1,2,3,4,5,6,7,8], length = 9. Duplicate 0 is ignored.
Example 3 (Edge Case)
Input: nums = []
Output: 0
Empty array — return 0.

Constraints

  • 0 ≤ nums.length ≤ 10⁵
  • -10⁹ ≤ nums[i] ≤ 10⁹
  • Must solve in O(n) time

Approaches Comparison

Approach Time Space Notes
Brute Force (nested loop) O(n³) O(1) For each number, count its streak with nested loops. TLE on large input.
Sort + Walk O(n log n) O(1)–O(n) Sort, then scan. Clean but doesn't meet the O(n) requirement.
✅ Hash Set (Optimal) O(n) O(n) Only start counting from sequence start. Each number visited once.

Approach 1 — Brute Force O(n³)

TimeO(n³)
SpaceO(1)

For every element, check if n+1, n+2… exist by scanning the entire array. Three nested loops = cubic time. Fails with TLE for n = 10⁵.

def longestConsecutive(nums: list[int]) -> int:
    longest = 0
    for n in nums:
        current = n
        streak = 1
        while current + 1 in nums:   # O(n) scan each time
            current += 1
            streak += 1
        longest = max(longest, streak)
    return longest

# Time: O(n²) – the `in nums` scan is O(n) → O(n²) overall
# (even worse with list, but you can see the idea)
public int longestConsecutive(int[] nums) {
    int longest = 0;
    for (int n : nums) {
        int curr = n, streak = 1;
        while (contains(nums, curr + 1)) {
            curr++;
            streak++;
        }
        longest = Math.max(longest, streak);
    }
    return longest;
}

private boolean contains(int[] nums, int val) {
    for (int n : nums) if (n == val) return true;
    return false;
} // O(n³) total

Approach 2 — Sort then Walk O(n log n)

TimeO(n log n)
SpaceO(1)*

Sort the array first, then walk through it counting consecutive elements. Skip duplicates. Clear and easy to code, but doesn't meet the O(n) constraint.

⚠ Interviewer will push back

This is correct and a valid stepping-stone answer. But the problem explicitly requires O(n). If you present this, immediately say: "This is O(n log n) due to sorting. I can optimize to O(n) using a Hash Set. Shall I continue?"

def longestConsecutive(nums: list[int]) -> int:
    if not nums:
        return 0
    
    nums.sort()
    longest = 1
    current_streak = 1
    
    for i in range(1, len(nums)):
        if nums[i] == nums[i - 1]:
            continue           # skip duplicates
        elif nums[i] == nums[i - 1] + 1:
            current_streak += 1
            longest = max(longest, current_streak)
        else:
            current_streak = 1
    
    return longest
public int longestConsecutive(int[] nums) {
    if (nums.length == 0) return 0;
    Arrays.sort(nums);
    int longest = 1, streak = 1;
    for (int i = 1; i < nums.length; i++) {
        if (nums[i] == nums[i-1]) continue;      // skip dups
        if (nums[i] == nums[i-1] + 1) {
            longest = Math.max(longest, ++streak);
        } else {
            streak = 1;
        }
    }
    return longest;
}

Approach 3 — Hash Set (Optimal ✅) O(n)

TimeO(n)
SpaceO(n)
💡 The Key Insight

A number n is the start of a consecutive sequence if and only if n-1 does NOT exist in the set. Only start counting from sequence starts — so each number is visited at most twice (once for the set, once during count). Total = O(n).

Algorithm:

  1. Put all numbers into a set (O(n), O(1) lookup).
  2. For each number n in the set: if n-1 is NOT in the set → n is a sequence start.
  3. Count upwards from the start: n+1, n+2… until the sequence breaks.
  4. Track the max streak seen.

Step-by-step: nums = [100, 4, 200, 1, 3, 2]
1
Build hash set from array (deduplicated).
set = {1, 2, 3, 4, 100, 200}
2
Check n=100: is 99 in set? No → sequence start. Count: 100, (101? No) → streak=1.
longest = 1
3
Check n=4: is 3 in set? Yes → NOT a start. Skip.
longest = 1 (unchanged)
4
Check n=200: is 199 in set? No → sequence start. Count: 200, (201? No) → streak=1.
longest = 1
5
Check n=1: is 0 in set? No → sequence start! Count: 1→2→3→4, (5? No) → streak=4.
longest = 4 ✅
6
n=2, n=3 have predecessors in set → not starts. Return longest.
Answer = 4
def longestConsecutive(nums: list[int]) -> int:
    num_set = set(nums)   # O(n) build
    longest = 0

    for n in num_set:
        # Only start counting from sequence beginnings
        if n - 1 not in num_set:
            current = n
            streak = 1

            while current + 1 in num_set:
                current += 1
                streak += 1

            longest = max(longest, streak)

    return longest
public int longestConsecutive(int[] nums) {
    Set<Integer> set = new HashSet<>();
    for (int n : nums) set.add(n);

    int longest = 0;

    for (int n : set) {
        if (!set.contains(n - 1)) {   // sequence start
            int current = n, streak = 1;
            while (set.contains(current + 1)) {
                current++;
                streak++;
            }
            longest = Math.max(longest, streak);
        }
    }
    return longest;
}
var longestConsecutive = function(nums) {

func longestConsecutive(nums []int) int {
    set := make(map[int]bool)
    for _, n := range nums {
        set[n] = true
    }

    longest := 0
    for n := range set {
        if !set[n-1] { // sequence start
            curr, streak := n, 1
            for set[curr+1] {
                curr++
                streak++
            }
            if streak > longest {
                longest = streak
            }
        }
    }
    return longest
}
Why is this truly O(n)?

The outer loop runs O(n) iterations. The inner while loop over a sequence of length L runs L iterations. Crucially, these inner loops are NOT nested per iteration — combined across ALL outer iterations, they run at most n total steps (each number is counted once). Total: O(n + n) = O(n).

🎯 Interview Playbook

  1. Clarify: "Can the array have duplicates?" (yes — handle by using a set). "Can it be empty?" (yes — return 0).
  2. Brute → Better → Optimal: Mention brute force (O(n²) with set, O(n³) without), then sort approach, then explain the Hash Set insight. Don't jump straight to optimal — show your thought process.
  3. State the key insight clearly: "We only start counting from the beginning of a sequence — when n-1 doesn't exist in the set." This is what interviewers want to hear.
  4. Complexity analysis must explain WHY it's O(n): Many candidates say O(n) but can't justify it. Use the amortized argument — each element is processed at most once by the inner while loop across ALL outer iterations.
  5. Common follow-up: "What if the input is a stream?" → Can't use the same approach; need a Union-Find or sorted structure.
  6. Companies that asked this: Google, Amazon, Meta, Microsoft, Apple, Uber.
