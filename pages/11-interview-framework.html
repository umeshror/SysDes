System Design Interview Framework

Module 15  |  4-Step Framework · Clarification · High-Level Design · Deep Dive · Wrap-up

The 4-Step System Design Framework

A structured approach is critical in a 45-60 minute interview to ensure you cover all necessary ground without getting stuck in the weeds early on.

1. Clarify & Scope

(5-10 mins)

  • Identify users and use cases
  • Functional vs. Non-functional requirements
  • Constraints (DAU, storage, latency)
  • "How many users?" / "What's the peak RPS?"

2. High-Level Design

(10-15 mins)

  • Sketch core components (LB, API, DB)
  • Define data flow between components
  • Choose the database type (SQL vs. NoSQL)
  • Verify the design meets functional reqs

3. Deep Dive

(15-25 mins)

  • Apply scaling patterns (Sharding, Caching)
  • Address failures (Replication, Multi-region)
  • Detail specific APIs or Data Schemas
  • Solve for performance bottlenecks

4. Wrap Up

(5 mins)

  • Summarize the final architecture
  • Mention alternative approaches discussed
  • Identify remaining weak points/limitations
  • Suggest monitoring/observability metrics

Step 1: Clarification & Scoping

Never start designing immediately. Spend the first 5-10 minutes asking questions to eliminate ambiguity. Interviewer expectations vary, so you must define the world you are building.

Example Questions for "Design Twitter"
  • "Can users follow each other?" (Focus: Social Graph)
  • "Do we need to support images and videos?" (Focus: Asset Storage, CDN)
  • "How many users are active daily?" (Focus: Scale, Throughput)
  • "Is the feed sorted by time or relevance?" (Focus: Ranking service)

Step 2: High-Level Design (Proposing a Skeleton)

Your goal is to get a working end-to-end design on the board. Don't worry about optimization yet.

graph LR
    User[Web/Mobile Client] --> LB[Load Balancer]
    LB --> API[API Gateway]
    API --> Auth[Auth Service]
    API --> Core[Core Business Logic]
    Core --> DB[(Primary Store)]
    Core --> Cache([Read Cache])

Generic high-level architecture skeleton

Step 3: Design Deep Dive (The "Meat" of the Interview)

This is where you show your expertise. The interviewer will usually guide you toward specific bottlenecks.

Problem Deep Dive Pattern
Huge write volume LSM-Trees, Sharding, Message Queues (Buffer)
Huge read volume Caching (Redis), Read Replicas, CDN
Slow queries Indexing, Denormalization, Materialized Views
Single point of failure Multi-leader replication, Heartbeats, Failover

Step 4: Wrap-up & Trade-offs

End on a strong note by identifying what your design *doesn't* do well. This shows maturity. No system is perfect; every design choice is a trade-off.

Pro-Tip: "The Two-Option Approach"

When making a big decision (e.g., choosing a DB), present two options, explain the trade-offs of each, and then make a recommendation based on the constraints you established in Step 1.
