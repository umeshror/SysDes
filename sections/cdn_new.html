Why CDNs Exist: The Speed of Light Problem

Light travels through fiber at ~200,000 km/s. A round trip from New York to London (~6,800 km) takes at minimum 34ms — just physics, nothing you can optimize away. A user in Sydney querying a server in Virginia adds ~160ms minimum. CDNs solve this by placing content physically close to users.

How CDNs Work

Points of Presence (PoPs)
CDN providers operate hundreds of PoPs globally — data centers with caching servers in major cities. Cloudflare has 300+ PoPs; Akamai has 4,100+. When a user requests content, DNS routes them to the nearest PoP via Anycast routing.
Anycast DNS Routing
All CDN PoPs advertise the same IP address. BGP (the internet's routing protocol) automatically routes any request to the topologically nearest PoP — no user-side configuration needed.
Cache Fill (Origin Pull)
On a cache miss at the PoP, the CDN fetches from origin, caches the response for the TTL (set by Cache-Control header), and serves future requests from edge. For popular content, subsequent requests never touch origin until TTL expires.
Cache HIT ratio goal: >95%
A 95% cache hit ratio means only 5% of requests reach origin. If your origin costs $0.02/request and you serve 1B requests/day, that's $1M/day at origin vs. $50K/day with CDN. Cache ratio depends on URL design (avoid random query strings) and TTL settings.

CDN Invalidation Strategies

Cache Invalidation is the Hard Part

Once served, a cached response lives at every PoP for TTL seconds. If you deploy a bug fix, old users see the broken version until TTL expires (or you purge). Strategies:

  • Versioned URLs (best): app.a3f2c1.js — old URL is gone, new URL is always fresh. No invalidation needed. Used by all major frontend frameworks.
  • Purge API: Call CDN's purge endpoint to evict specific URLs immediately. Cloudflare processes purges in <150ms globally. Costs money at high volume.
  • stale-while-revalidate: Serve stale content immediately; refresh in background. User never waits. Max staleness is bounded.
  • Short TTL: Accept slightly higher origin load in exchange for near-real-time freshness. 30–60 second TTL for dynamic but cacheable content.

Netflix Open Connect: A CDN Built from Scratch

Scale
Netflix delivers 15%+ of global internet downstream traffic. At peak, ~700 Gbps from a single large ISP-embedded Open Connect Appliance (OCA). They built their own CDN because commercial CDNs couldn't give them the control, cost structure, or throughput they needed.
ISP Embedding
Netflix places OCAs inside ISP data centers and exchanges (free hardware to the ISP). No AWS egress fees, direct fiber to the ISP's network — ultra-low latency for the last mile. The appliance only serves pre-loaded content (files, not requests) pushed to it nightly from Netflix's centralized fill servers.
Proactive caching
Netflix predicts what content a region will watch tomorrow (based on viewing trends and release schedules) and pre-populates OCAs overnight. 90%+ cache hit ratio for popular titles before anyone requests them.

Edge Computing: Beyond Caching

Modern CDN platforms (Cloudflare Workers, AWS Lambda@Edge, Fastly Compute) let you run code at the edge, not just cache content. This enables:

Traditional CDN

  • Cache and serve static assets
  • Configured via rules (no custom logic possible)
  • Origin always needed for dynamic content

Edge Computing (Cloudflare Workers)

  • Run JS/WASM at every PoP with <1ms cold start
  • A/B testing at the edge (no origin round trip)
  • Auth token validation without hitting origin
  • Personalised HTML generation at edge latency
  • Image transcoding / resizing on-the-fly
